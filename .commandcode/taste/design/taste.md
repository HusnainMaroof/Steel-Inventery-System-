# Taste

## Visual design
- Prefers a minimal, professional, monochrome UI — roughly 90% black/white/gray — with thin 1px borders, rectangular cards, no gradients, no heavy rounding, and subtle or no shadows. Confidence: 0.95
- Uses a specific neutral design token palette: canvas `#F8F8F7`, cards `#FFFFFF`, primary text `#171717`, secondary text `#737373`, borders `#E5E5E5`, dark highlight card `#111111`. Confidence: 0.95
- Color is reserved for status only, in muted tones: muted red for due/warning and muted green for paid/positive; avoids strong or bright colors elsewhere. Confidence: 0.95
- Card/panel radius is 8px; inputs/buttons slightly smaller (6px); borders 1px solid `#E5E5E5`. Confidence: 0.9
- Keeps generous whitespace: dashboard padding ~24–32px, card padding ~20–24px, card gaps ~12–16px, section gaps ~16–24px. Confidence: 0.8
- Dislikes congested/cramped popups; when an entry modal got too busy, the user's fix is to remove panes/features (e.g. the right-side invoice preview) and fall back to a compact centered modal (roughly 3xl) rather than pushing it near-fullscreen — the goal is a focused, breathable single-column form with clearly separated sections (date/party → items → money → totals). Confidence: 0.8
- Prefers entry modals (e.g. New Sale) as a single clean column without side-by-side panes once a live preview is out of the popup: date/customer on top, then the items list, then discount/tax/paid, with the totals pinned and always visible. The earlier full-height two-pane workspace only applied while a live preview lived in the form, and that pane was removed on the user's request. Confidence: 0.8
- Modal layouts should be responsive: two-pane content (form + live preview) should sit side-by-side only on wide/xl screens and stack full-width below that breakpoint, rather than squeezing both panes onto smaller viewports. Responsiveness of such layouts is an explicit requirement the user calls out. Confidence: 0.85
- Prefers a clean modern sans typeface app-wide (Inter primary, Geist as alternative); small labels set uppercase with letter-spacing and weight 500–600; main numbers bold (600–700) with tabular figures; table text at weight 500; secondary text at 400. Confidence: 0.9
- Uses the black/dark card treatment for exactly one "priority" KPI (the single most important business metric, e.g., Total Stock) rather than making every card prominent. Confidence: 0.95
- Wants the main dashboard to be stats/KPI-only — detailed stat cards (Stock in Hand, Stock Worth, Sales, Profit, Payment Dues, Customer Payment Dues, Mills Payment Dues) and nothing else; explicitly removed the Recent Purchases / Recent Sales lists and the per-item/quality table from the dashboard (those belong on dedicated pages, not the overview). Confidence: 0.85
- Prefers the dashboard to be scoped around a selectable business entity rather than fixed tabbed widget sections: a product dropdown at the top-left ("All Products — entire depot" plus each product) drives every KPI and table below, with all cards/lists filtering to the selected product. Explicitly removed the fixed top tabs (Customer Balance, Outstanding Bill, Recent Purchases, Quick Actions) and the old welcome content in favor of this. Confidence: 0.75
- The dashboard product dropdown should default to the "All" view on load — show the whole depot by default rather than a specific product, with individual products selectable from there. Confidence: 0.85
- Branding/business identity is "New Ittifaq Steel Depot & Cement Agency" — use this name in sidebar, page headers, and other UI copy rather than stale/generic names. Confidence: 0.9
- When the user calls the UI/UX "old" and asks for a "new layout structure", prefers status-driven document layouts over plain tables: per-row Total / Paid / Due columns, small tinted status chips (Paid green, Partial amber, Unpaid red, Advance blue), a summary strip above the list (total invoices, count with balance due, total outstanding), and row-level actions (Receive / Open) instead of boxy stat footers. Confidence: 0.75

## Data entry & flows
- Wants busy/cluttered entry forms redesigned into a spacious modal popup with clearly labelled sections (Date → party → products/items → money), with the New Sale flow mirroring the purchase form's structure for consistency across modules. Confidence: 0.8
- Does not want a live invoice preview embedded in the New Sale entry popup — explicitly asked to remove the right-side invoice preview because the popup felt cluttered and the UX was bad; invoice-style rendering belongs on dedicated saved-sale detail/print surfaces, not duplicated inside data entry. Confidence: 0.85
- Wants derived money values computed automatically and shown live as a full breakdown (Subtotal → Discount → Taxable → Tax → Grand Total → Paid Now → Remaining Due) rather than making the operator do the math by hand. Confidence: 0.85
- Prefers a filter-then-add flow for adding line items (cascading product → item → quality → mill/source dropdowns feeding one “+ Add Item” action; each added item becomes its own card where only quantity is edited inline — unit price is not editable; options surface available stock and the lot's auto sell price). The add-item step must NOT open a pop-up — the user explicitly rejected popup-based adding while creating an invoice (“when I add, don't open a pop-up”): the cascading filter row sits always-visible inline on the creation page and appended items appear as inline cards, so the whole creation flow is free of nested popups. Confidence: 0.9
- Prefers keeping creation flows as popups rather than switching to a dedicated full-page view — but the popup must be screen-sized: “+ New Sale” opens a large overlay taking ~70–80% of the viewport (the sales list stays visible and dimmed behind it) with Cancel/Save in its header; on save the overlay closes and the fresh invoice's detail opens. The earlier full-page creation screen was explicitly rejected in favor of keeping the popup and making it big. Confidence: 0.9
- Prices on customer invoices must be locked, not typed at sale time: when an item is added to a sale, its unit price auto-fills from the stock lot's recorded selling price ("Your Selling Price" set on the purchase) and the added-item row shows that price read-only; if no sell price was recorded, fall back to landed cost + ~15% so the sale can still be saved. Confidence: 0.85
- Modal entry flows (e.g., New Sale, New Purchase) should stay visually consistent with each other so the UI feels like one coherent system — shared section/divider rhythm (date/party → items → money → totals) and matching compact modal sizing rather than a form-plus-preview split. Confidence: 0.7
- On full-page creation views, prefers running totals in a compact right-side rail (Summary card: subtotal, discount %/tax %, grand total, paid now, remaining due, and the Save button) over bottom totals — chosen explicitly when asked between “compact totals panel” and “bottom totals”. The rail is sticky on xl screens and stacks below the content on smaller ones. Confidence: 0.8
