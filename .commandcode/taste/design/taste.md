# Taste

## Visual design
- Prefers a minimal, professional, monochrome UI — roughly 90% black/white/gray — with thin 1px borders, rectangular cards, no gradients, no heavy rounding, and subtle or no shadows. Confidence: 0.95
- Uses a specific neutral design token palette: canvas `#F8F8F7`, cards `#FFFFFF`, primary text `#171717`, borders `#E5E5E5`, dark highlight card `#111111`. (The gray secondary-text token `#737373` is superseded — see the no-gray-text rule below.) Confidence: 0.95
- No gray text anywhere — labels, hints, and secondary copy render in full-contrast black or white only: black `#171717` on white/light surfaces, white on black/dark surfaces. The user explicitly banned gray/neutral text tones ("don't use a gray color … if we have a BG white then use black color … BG black but we are using gray so use white color"), and every `text-neutral-400`/`text-neutral-500` on the dashboard was replaced with `text-[#171717]` or `text-white`. Reaffirmed for the Purchases list table ("All full black color, don't use gray color at all") — the ban is app-wide, covering list tables, column headers, and mobile cards, not just one surface. Where hierarchy used to come from gray, use black at reduced opacity (`text-black/60` for secondary/spec lines) rather than gray tokens; status accents (muted red/green) are unaffected. Confidence: 0.95
- Color is reserved for status only, in muted tones: muted red for due/warning and muted green for paid/positive; avoids strong or bright colors elsewhere. Confidence: 0.95
- Card/panel radius is 8px; inputs/buttons slightly smaller (6px); borders 1px solid `#E5E5E5`. Confidence: 0.9
- Keeps generous whitespace: dashboard padding ~24–32px, card padding ~20–24px, card gaps ~12–16px, section gaps ~16–24px. Confidence: 0.8
- But wants the overall UI slightly compact: asked to "make the website a bit small" and re-confirmed the resulting text size is right ("when you small the text, text is small it's good now"). FINAL mechanism: root `font-size: 90%` on `html` — shrinks text and spacing without touching layout widths, and is a one-line knob for overall density. Confidence: 0.85
- The app UI must fill the ENTIRE viewport width — sidebar and every section stretch edge-to-edge with no dead space or right-hand gap; the user filed "the dashboard section is taking not fully size of the screen" as a bug twice ("I want to use the full screen"). Root cause was the global `zoom: 0.9`: zoom shrinks the rendered content but not the space it occupies, so the layout can never reliably fill the screen — it was removed entirely in favor of root font-size for compactness. Never reintroduce `zoom`/transform-scale on `html`/`body` for overall sizing, and keep the app shell free of max-width containers; compact density comes from root font-size, never from scaling that breaks full-bleed layout. Confidence: 0.9
- Dislikes congested/cramped popups; when an entry modal got too busy, the user's fix is to remove panes/features (e.g. the right-side invoice preview) and fall back to a compact centered modal (roughly 3xl) rather than pushing it near-fullscreen — the goal is a focused, breathable single-column form with clearly separated sections (date/party → items → money → totals). Confidence: 0.8
- Prefers entry modals (e.g. New Sale) as a single clean column without side-by-side panes once a live preview is out of the popup: date/customer on top, then the items list, then discount/tax/paid, with the totals pinned and always visible. The earlier full-height two-pane workspace only applied while a live preview lived in the form, and that pane was removed on the user's request. Confidence: 0.8
- Modal layouts should be responsive: two-pane content (form + live preview) should sit side-by-side only on wide/xl screens and stack full-width below that breakpoint, rather than squeezing both panes onto smaller viewports. Responsiveness of such layouts is an explicit requirement the user calls out. Confidence: 0.85
- Prefers a clean modern sans typeface app-wide (Inter primary, Geist as alternative); small labels set uppercase with letter-spacing and weight 500–600; main numbers bold (600–700) with tabular figures; table text at weight 500; secondary text at 400. Confidence: 0.9
- Uses the black/dark card treatment for exactly one "priority" KPI (the single most important business metric, e.g., Total Stock) rather than making every card prominent. Confidence: 0.95
- Text on black/dark surfaces must stay high-contrast and readable (white) regardless of global CSS: when the black Total row in the sale-detail popup rendered black-on-black because a global `td { color: black }` rule overrode the white utility class, the user flagged it as a bug to fix. Confidence: 0.6
